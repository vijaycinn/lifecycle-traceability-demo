Starter GitHub Actions: Enforce Issue Link on PRs + Auto-Add Issues to vijaycinn Project v2 Copy-Paste YAML

1. Enforce Fixes #N / Refs #N / AB#N on PRs (pair with a Branch Ruleset required check):

name: PR Traceability Gate
on:
  pull_request:
    types: [opened, edited, synchronize, reopened]
jobs:
  require-issue-link:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/github-script@v7
        with:
          script: |
            const body = context.payload.pull_request.body || '';
            const hasLink = /((close[sd]?|fix(e[sd])?|resolve[sd]?|refs)\s+#\d+|AB#\d+)/i.test(body);
            if (!hasLink) core.setFailed('PR description must reference an issue (e.g., Fixes #12, Refs #12, or AB#7).');

2. Auto-add Issues & PRs to a personal vijaycinn Project v2 (use a repo secret PROJECT_PAT with project scope):

name: Sync to Project Board
on:
  issues: { types: [opened] }
  pull_request: { types: [opened] }
jobs:
  add-to-project:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/add-to-project@v1.0.2
        with:
          project-url: https://github.com/users/vijaycinn/projects/2
          github-token: ${{ secrets.PROJECT_PAT }}

1. Is Copilot Code Review in Azure DevOps GA or Public Preview? Release Status

Microsoft's Nov 17, 2026 DevOps Blog announced that "Copilot Code Review for Azure DevOps is now generally available." However, as of 2026-11-19, Microsoft Learn's Sprint 279–281 release notes and Features Timeline (ms.date 2026-11-06) still label it Public Preview, and Sprint 282 (2026-11-17) has no GA line item yet. Frame it honestly to customers as announced GA Nov 17, 2026 while Learn release notes catch up.

2. How many AI credits does each Azure DevOps code review consume? Credits & Effort

Azure DevOps docs publish no fixed ADO credit table—each completed review meters input, output, and cached tokens at 1 GitHub AI credit = $0.01 USD using an undisclosed model, and defers to GitHub's reference ranges: Lite $0.05–$1 (avg ~$0.25 ≈ 25 credits), Balanced $0.25–$5 (avg ~$1.50 ≈ 150 credits), and Max $1.50–$25 (avg ~$10 ≈ 1,000 credits). Note that ADO Sprint 280 names Lite/Balanced while Learn screenshots show Low/Medium/High; actual consumption scales with PR diff size and custom instructions. Whether cancelled/failed reviews incur partial token charges is undocumented.

3. How do we estimate monthly AzDO review costs and prevent runaway spend? Cost Estimation

Microsoft's official method: enable on 1–2 pilot repos, compare effort levels, and monitor daily usage in Azure Cost Management under GitHub → GitHub Copilot for AzDO (grouped by _organizationname_ / _projectname_; 48-hour lag).
Planning formula: Monthly Cost ≈ Active PRs/mo × (1 + Manual Re-reviews/PR) × Avg Cost at Effort Level (e.g., 500 PRs × 1.5 reviews × $1.50 Balanced ≈ $1,125/mo vs. ~$188/mo at Lite).
Critical spend warning: Azure budgets alert only—they do NOT stop reviews (unlike GitHub.com budgets). Control cost by locking Project default effort to Lite/Balanced, keeping automatic review branch policies off on noisy repos, and capping PR eligibility (≤10 GB repo, ≤100 files/changes, 1 completed review per merge commit, no auto re-review on new pushes).

4. Do GitHub Copilot Business/Enterprise seat credits apply to Azure DevOps reviews? Licensing

No. Per the MS Learn FAQ, "usage in Azure DevOps doesn't use AI credits from GitHub Copilot plans." All AzDO Copilot reviews bill strictly to the linked Azure subscription—even for users who already hold GitHub Copilot Business ($19) or Enterprise ($39) seats. Users also need at least ADO Basic access (Stakeholders have no Azure Repos access in private projects).

5. Can Copilot block merges, run on self-hosted agents, or honor ADO EU data residency? Governance Limits

No to all three today: (1) Copilot always posts a Comment review (cannot approve or satisfy required reviewers; formal PR Approval + File Exclusions are on the 2027 Q1 roadmap); (2) supported runners are Microsoft-hosted Azure Pipelines or Managed DevOps Pools (self-hosted agents are unsupported, TFVC is unsupported, and failed review JSON logs appear under the default Azure Pipelines pool); (3) Copilot processing does not follow ADO org data residency (e.g., an EU org may be processed in the US), though customer code is not used to train foundation models.

What This Demonstrates & Why Customers Care

  • Encode engineering standards once, enforce on every PR: Platform and security teams define org, project, and repo rules once—Copilot applies those exact test, SAML security, and Clarity sync checks on every PR instead of senior engineers repeating the same comments manually.
  • Path-scoped precision from target branch: Repo rules live on main under /.azuredevops/ and target specific extensions (applyTo: "**/*.js,**/*.mjs") with 1-click Apply suggestion fixes directly in Azure Repos.

Human Governance Still Holds the Merge Gate

  • Copilot advises; humans approve: Azure Repos Copilot Code Review always posts a Comment review—it never approves PRs or bypasses required human reviewers.
  • Policy-enforced closure: Pairing Copilot with Check for linked work items = Required and Check for comment resolution = On on main holds the merge until every Copilot thread is resolved or answered.

Technical Appendix: Exact Staged Instruction Files on main (PR #5) Target-Branch Rules

Unlike GitHub.com (which reads from the head branch), Azure DevOps reads custom instructions strictly from the PR's target branch (main), merged here via PR #5 (commit 84419c45).

- SAML & Security: Verify signatureValid, notBefore/notOnOrAfter 120s clock-skew bounds, finite timestamp guards (Number.isFinite), and replay-cache protection (IdempotencyStore).
